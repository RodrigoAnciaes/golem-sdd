# Referência: `mission.md`

Carregue este arquivo ao escrever ou revisar a missão.

## Seções obrigatórias

| Seção | O que precisa estar lá | Sem isso acontece o quê |
|---|---|---|
| Em uma frase | quem é servido, que resultado, sem qual dor | o agente inventa o posicionamento em cada fase |
| Problema | fatos do estado atual, com custo mensurável | features viram opinião, não solução |
| O que fazemos | capacidades, não implementação | a stack vaza para a missão e a engessa |
| A quem servimos | personas com nível técnico e critério de valor | interface escrita para ninguém |
| Como é o sucesso | critérios verificáveis (sim/não ou número) | ninguém sabe declarar o projeto pronto |
| Não-objetivos | o que fica de fora **e por quê** | escopo cresce a cada fase |
| Glossário | termos do domínio, definição operacional | o agente traduz termo de negócio errado |

## O que separa uma missão boa de uma inútil

- **Cada linha precisa poder reprovar alguma ideia.** Missão que aceita qualquer feature não é
  missão, é folheto.
- **Sucesso é observável.** "Melhorar a experiência" não vale; "a atendente fecha um chamado
  simples em menos de 5 minutos" vale.
- **Persona tem contexto, não rótulo.** "Recepcionista" não diz nada; "recepcionista que remarca
  30 consultas por dia pelo telefone e não sabe de cabeça quais médicos aceitam encaixe" diz tudo.
- **Não-objetivo é declaração de paz.** Ele existe para você não relitigar a mesma discussão na
  Fase 7.

## Falhas comuns

| Sintoma | Correção |
|---|---|
| Missão que descreve o software, não o problema | comece pelo que dói hoje, sem citar tecnologia |
| Lista de features disfarçada de capacidades | agrupe em 3 a 6 capacidades; feature é roadmap |
| "Sucesso = entregar no prazo" | prazo é restrição; sucesso é efeito no usuário |
| Glossário ausente em domínio técnico | todo termo que um estranho pediria para explicar entra |
| Não-objetivos vazios | pergunte: "o que alguém vai supor que faremos e não faremos?" |

## Perguntas de entrevista

1. Se este projeto não existisse daqui a um ano, o que continuaria doendo, e para quem?
2. Quem usa isso todo dia, e o que essa pessoa faz hoje no lugar?
3. Como você vai saber, olhando um número ou uma tela, que valeu a pena?
4. O que as pessoas vão pedir que a gente **não** vai fazer?
5. Que palavras deste domínio eu tenho que usar exatamente como você usa?
